Programme / Intake / Approved Project Allocation Change

This page explains the proposed change from Internship Category-based setup to Education Level-based Programme setup. Solution 1 is updated to an approved-project allocation model: AD submits the Project, IO approves the submitted Project first, the system then recommends Programme + Intake allocation records, and IO finally confirms or amends the allocation. The system should not recommend Programme allocation before IO project approval.

Advantages

  • Programme / Intake and AD Project submission lifecycle can progress in parallel.
  • The system only provides Programme / Intake recommendations for approved Projects, reducing invalid recommendations.
  • IO responsibility is clearer: approve the Project first, then final-confirm allocation.

Risks

  • System recommendation depends on field completeness and data quality.
  • If Programme / Intake setup is incomplete, the system suggestion may be inaccurate.
  • The UI must clearly separate Submitted, Pending IO Approval, Approved, Recommendation Generated and Allocation Confirmed.

Business Input Needed

  • Which fields and weights should drive the system recommendation?
  • Can IO directly change the suggested Programme / Intake?
  • Should the Project ID be generated at AD submission or only after IO approval?

Report Purpose

  • View Project allocation records across Programmes and Intakes.
  • Confirm which AD submissions have been approved by IO, which have system recommendations generated, and which allocation records still await IO final confirmation.
  • Connect allocated slots to offer issuance outcomes.
Slot → Offer linkageOnly Projects that enter Programme / Intake allocation create offerable slots; offers issued / accepted / remaining show whether the intake is filled or still has capacity.

Exceptions to Surface

  • AD has submitted the Project, but IO has not approved it yet, so the system should not generate Programme / Intake recommendations.
  • Project has been approved and the system has recommended Programme / Intake, but allocation is not final-confirmed yet.
  • Project has allocated slots but offers have not been issued.

Allowed Rule

One Project Request / Project can support multiple Intakes / Education Levels, but capacity and timeline validation is required.
