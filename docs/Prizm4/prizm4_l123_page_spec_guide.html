PRIZM 4 · TOA Page-level Rules

Updated interpretation: L1/L2/L3 are not compliance layers. They are TOA page levels. L1 is Dashboard, L2 is List Page, and L3 is Create / Modify / Review / Detail. Official PRIZM requirements remain global constraints across all three levels.

L1 = Dashboard L2 = List Page L3 = Create / Modify / Review / Detail /programmes/new belongs to L3, with L2 handoff rules

M Page Level Map

Global PRIZM rules such as stable components, semantic tokens, no raw colours, no Enterprise glass, and air-gap discipline apply across every level. The L1/L2/L3 names below describe page types and workflow depth.

L1

Dashboard

Landing and overview surfaces. Prioritise summary metrics, action alerts, workstream context, and navigation into L2 lists.

L2

List Page

Operational list surfaces such as Programmes, Projects, Requests, and Applications. Includes toolbar, filters, table/card list, pagination, and entry points into L3 tasks.

L3

Create / Modify / Review / Detail

Task-focused pages and existing-object details. Includes multi-step creation, edit flows, review/confirm screens, detail pages, and related-record panels.

L1.1 L1 · Card Primitive

PRIZM Card is a stable primitive. Use components/ui/card.tsx for primary detail-page and dashboard surfaces before introducing page-local div.card structures.

Card partPRIZM baselineTOA rule
Rootrounded-lg border border-border bg-surface text-fg shadow-smUse for detail sections and compact dashboard metric surfaces.
HeaderTitle + description region with p-6 and compact vertical gap.Do not make ordinary row labels look like section headings.
Titletext-lg font-semibold leading-noneUse card title scale only for real card titles.
Description / body copytext-sm text-fg-mutedHelper copy and explanatory text should stay body/caption scale.
Contentp-6 pt-0Use dividers/subsection headings for internal grouping instead of nesting cards.
FooterAction row with p-6 pt-0.Footer actions still use PRIZM Button variants.
TOA constraint: Card is a grouping surface, not a typography escape hatch. Text inside cards must still follow the relevant list/detail typography table. Avoid rounded-xl unless a specific existing PRIZM pattern requires it.

G2 Governance · MD Snippets

L2 List Page handoff to L3

- L2 list pages are operational entry points. Primary actions such as `Create Programme` may route into L3 task pages. - When an L2 page opens an L3 create / modify / review / detail page, keep the L2 list state predictable when the user returns. - The Create Programme route `/programmes/new` is an L3 task page entered from the L2 Programmes list.

Stepper / Wizard rule

- Create / Modify pages may use a TOA Stepper wrapper for multi-step workflows. It is not an official PRIZM component. - Do not create or document `components/ui/stepper.tsx` as a PRIZM primitive unless it is confirmed stable in the PRIZM registry. - The wrapper must use semantic tokens, accessible step labels, visible current-step state, and keyboard-safe navigation.

Education Level option cards

- Education Level selection should use PRIZM Radio Group when only one education level can be selected. - If multiple education levels are allowed, use PRIZM Checkbox group instead. - The bordered card visual is a TOA option-card wrapper and must preserve radio/checkbox semantics, keyboard access, and visible focus states.

Eligibility Criteria summary row

- Eligibility Criteria summary row is a TOA CriteriaSummaryRow pattern, not a PRIZM primitive. - It should compose stable primitives such as Card, Button, Text, and Icon. - Do not show a clickable chevron or link affordance when the row is disabled or not configured.

PRIZM 4 · TOA 页面级规范

更新后的理解：L1/L2/L3 不是合规层级，而是 TOA 的页面层级。L1 是 Dashboard，L2 是 List Page，L3 是 Create / Modify / Review / Detail。PRIZM 官方约束作为全局规则，适用于全部页面层级。

L1 = Dashboard L2 = List Page L3 = Create / Modify / Review / Detail /programmes/new 属于 L3，但需要写清 L2 handoff

M 页面层级地图

Stable components、semantic tokens、禁止 raw colour、Enterprise 禁用 glass、air-gap discipline 等 PRIZM 官方规则适用于所有层级。下面的 L1/L2/L3 是页面类型和任务深度。

L1

Dashboard

入口和概览页面。重点是 summary metrics、action alerts、workstream context，以及进入 L2 列表页的导航。

L2

List Page

Programmes、Projects、Requests、Applications 这类运营列表页。包含 toolbar、filters、table/list、pagination，以及进入 L3 task pages 的入口。

L3

Create / Modify / Review / Detail

任务型页面和对象详情页。包含创建、编辑、review/confirm、detail，以及 related-record panels。

L1.1 L1 · Card Primitive

PRIZM Card 是 stable primitive。详情页主卡片和 dashboard summary surfaces 应优先使用 components/ui/card.tsx，不要先写页面局部的 div.card。

Card 部位PRIZM baselineTOA 规则
Rootrounded-lg border border-border bg-surface text-fg shadow-sm用于详情页主 section 和 compact dashboard metric surfaces。
HeaderTitle + description 区域，使用 p-6 和紧凑 vertical gap。普通 row label 不要做成 section heading 的视觉重量。
Titletext-lg font-semibold leading-none只有真正的 card title 才使用 card title scale。
Description / body copytext-sm text-fg-mutedHelper copy 和说明文字保持 body/caption scale。
Contentp-6 pt-0内部组织用 divider / subsection heading，不要 card 套 card。
FooterAction row，使用 p-6 pt-0。Footer 里的操作仍然使用 PRIZM Button variants。
TOA 约束：Card 是 grouping surface，不是放大字体的理由。Card 里的文字仍要遵守列表/详情页字体表。除非现有 PRIZM pattern 明确要求，否则避免 rounded-xl。
