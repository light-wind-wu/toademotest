# 系统逻辑补充说明

本文档用于记录在需求澄清及开发过程中确认的补充系统逻辑。仅写入已经由产品确认的规则；尚未确认的讨论内容不纳入本文档。

## 1. Programme 与 Intake 状态管理

**确认日期：** 2026-08-21  
**适用模块：** Internship  
**确认状态：** Confirmed

### 1.1 Draft Programme 的 Intake 管理

- Draft Programme 可以新增、修改和删除 Intakes。
- Draft Programme 下的所有 Intakes 只能处于 Draft 状态。

### 1.2 Active Programme 的 Intake 管理

- Active Programme 可以新增 Draft Intake。
- 已有 Intake 是否允许修改或删除，取决于 Intake 自身状态及是否已产生申请记录：
  - 尚未开放且没有 Application：可以修改或删除。
  - 已开放或已有 Application：不允许删除。
  - 已开放或已有 Application 后，申请窗口、实习日期等关键字段不允许直接修改。
  - 如业务上必须修改关键字段，应由 IO Admin 操作，填写修改原因并记录 Audit Log；如变更影响申请人，应通知受影响用户。
  - 已结束的 Intake 只读，不允许修改或删除。

### 1.3 Completed Programme 的 Intake 管理

- Completed Programme 下的已有 Intakes 全部只读。
- 不允许新增、修改或删除 Intake。
- 如下一年度或新一轮需要开办相同 Programme，应通过 Duplicate Programme 或 Create New Programme 建立新的 Programme，不应修改历史 Programme。

### 1.4 Completed Programme 重新变为 Active

- Completed Programme 正常情况下不允许直接 Mark as Active。
- 如果 Programme 因误操作被标记为 Completed，可由 IO Admin 执行 Reopen Programme。
- Reopen Programme 必须满足以下要求：
  - 填写 Reopen Reason；
  - 记录操作者及操作时间；
  - 记录 Audit Log；
  - 不得用于开启下一年度或新一轮 Programme。

### 1.5 删除 Programme 及其 Intakes

- 只有 Draft Programme 允许永久删除。
- Draft 阶段不得产生 Application、Interview、Offer、Onboarding 或其他下游业务记录。
- 删除 Programme 时，系统应同时删除：
  - 该 Programme 下的所有 Draft Intakes；
  - Programme、Intake 与 Project 之间的关联关系。
- 删除 Programme 或 Intake 时，不得删除 Project 本身。
- Active、Completed 或 Archived Programme 不允许永久删除。
- 删除操作仅允许 IO Admin 执行。
- 删除前应进行二次确认，并明确显示将被删除的 Intakes 数量。
- 系统应记录删除操作日志。

## 2. Intake 与 Project 匹配及 Placement 管理

**确认日期：** 2026-08-21  
**适用模块：** Internship  
**确认状态：** Confirmed

### 2.1 Project 匹配 Intake 的条件

一个 Project 只有同时满足以下全部条件，才可以匹配 Intake：

1. Project 的 Intern Category 与 Intake 适用的 Intern Category 完全一致。
2. Project 的 Internship Window 与 Intake 的 Internship Window 完全一致；仅存在日期重叠不视为匹配。
3. Project Duration 小于或等于 Intake Internship Window Duration。
4. Project 的 Remaining Placements 大于或等于 1。
5. Project 已通过审批。

以上条件均为 Hard Gate，IO 不允许 Override。

### 2.2 一个 Project 匹配多个 Intakes

- 一个 Project 只要满足上述全部条件，即可匹配多个 Intakes。
- Project 与 Intake 建立关联时，不消耗或预留 Placement。

### 2.3 Placement 消耗与 Pending Offer

- Placement 在 Applicant 接受 Offer 时消耗。
- Pending Offer 不消耗或预留 Placement。
- 系统不强制限制同一 Project 的 Pending Offer 数量；可能发生的超额风险由业务在线下协调。
- 当剩余 Placement 只有 1 个，但两个或以上已经发出的 Offer 先后被接受时，系统允许后续 Applicant 继续接受 Offer，即使最终接受人数超过 Project Placements。

### 2.4 Placement 释放

Applicant 接受 Offer 后，发生以下任一情况时，应释放已经消耗的 Placement：

- Applicant 撤回；
- Applicant 被终止；
- Applicant 未完成 Onboarding；
- Applicant 在 Internship 开始前取消。

### 2.5 Project 满额后的处理

当 Project 的 Placements 已满时：

- Project 不再显示在 Applicant 的 Ranking Project 列表中；
- Project 不再接受新的 Project Ranking；
- 不影响已经选择该 Project 且正在处理中的 Applications；
- 已经发出的 Offer 仍然允许 Applicant 接受。

### 2.6 Placement 释放后的处理

当 Placement 被释放并使 Project 再次存在可用 Placement 时：

- Project 重新显示在符合匹配条件的 Applicant Ranking Project 列表中；
- Project 重新接受新的 Project Ranking。
